Show HN: Crisol — zero-bloat multi-node benchmark dispatcher (no K8s, no Ray,
no Slurm). Stone-cold reproducible with seed 1729 + JSONL audit.

Kubernetes, Slurm and Ray exist to herd a datacenter. I built the opposite:
a dispatcher for the lab I actually have — a laptop, a tower with an RTX, a
spare headless box. 2 to 5 machines, not 500.

The gap it fills:
- Setting up Ray/Slurm/K8s for a handful of boxes is a nightmare of daemons,
  config and wasted RAM.
- Hand-rolled SSH scripts are fragile, produce zero traceability and hide real
  numbers.
- Everyone says "my model flies" while comparing different libs, dimensions
  and no warmup.

What Crisol does:
1. Pins the SEED (1729 by default), dimensions and warmup so numbers are
   comparable — reproducible by construction.
2. Appends an IMMUTABLE JSONL ledger per run: run_id, job, node, backend,
   status, exit code, elapsed, seed, full stdout/stderr.
3. Ships a zero-dependency HTTP receiver daemon for REMOTE dispatch with live
   NDJSON event streaming (real-time progress, metrics, gpu_stats).
4. ZERO dependencies beyond the Python standard library (stdlib-only smoke
   benchmark — no torch required; torch-smoke auto-registers when torch/CUDA
   is present).

The reproducible seed is 1729 — the taxi-cab number (the smallest integer
expressible as a sum of two positive cubes in two different ways:
1729 = 1^3 + 12^3 = 9^3 + 10^3). In Number Theory it's the Hardy–Ramanujan
number. In Crisol it's the pin that makes every run auditable and every
claim comparable.

The hetero story: the SAME job contract runs on Apple Silicon (MPS), NVIDIA
CUDA and plain cloud CPU — the backend is a first-class field, so `crisol run
torch-smoke --node m2` vs `--node wsl-rtx4060` produces ledger lines you can
actually diff.

Quick look:

    $ pip install crisol
    $ crisol status        # probe reachable nodes on this machine
    $ crisol jobs          # list registered benchmark contracts + seeds
    $ crisol run cpu-smoke # dispatch; immutable JSONL to results/2026-08-20.jsonl
    $ crisol run torch-smoke --node m2 --detach   # remote + background
    $ crisol listen <run_id> --node m2            # reconnect to the stream

    $ crisol run cpu-smoke
    ==================================================
      Job:       cpu-smoke
      Node:      local-cpu (cpu)
      Seed:      1729
      Status:    completed (exit 0)
      Elapsed:   0.8s
      Ledger:    ...\results\2026-08-20.jsonl
    ==================================================

Each run appends one honest line to the ledger:

    {"backend": "cpu", "elapsed_s": 0.8, "exit_code": 0, "job": "cpu-smoke",
     "node": "local-cpu", "run_id": "...", "seed": 1729, "status": "completed",
     "stdout": "...", "stderr": "", "timed_out": false, "ts": "..."}

Workloads emit crisol-protocol JSONL on stdout (lifecycle, progress, metrics,
result, gpu_stats) — a clean contract any dashboard/TUI can parse. All helpers
are pure and importable with ZERO deps.

MIT. Public. https://github.com/seed-source/crisol

## r/LocalLLaMA version (más densa, enfocada a benchmarks reproducibles)

**Silicio heterogéneo, sin teatro de orquestación.**

- **Heterogéneo desde el diseño.** El `backend` es un campo de primera clase:
  el mismo contrato de job corre en Apple Silicon (MPS), NVIDIA CUDA y CPU de
  cloud. No hay "huecos de plataforma": `crisol run torch-smoke --node m2` y
  `--node wsl-rtx4060` escriben líneas de ledger que de verdad se pueden
  comparar.
- **Seed fija `1729` por default** (número de Hardy–Ramanujan) + dimensiones +
  warm-up fijos. El resultado deja de ser "mi modelo vuela" y pasa a ser una
  métrica auditable que no cambia entre máquinas por capricho de la librería.
- **Ledger JSONL inmutable por run.** `run_id, job, node, backend, status,
  exit_code, elapsed_s, seed, stdout, stderr` — una línea por run, keyed by
  fecha. Auditoría real, no un README con promesas.
- **Cero overhead de K8s/Ray/Slurm.** Un daemon HTTP receptor opcional
  (stdlib) para dispatch remoto con streaming NDJSON en tiempo real
  (`progress`, `metrics`, `gpu_stats`) y re-conexión (`crisol listen`). Para
  2-5 máquinas no necesitas un data center — necesitas un contrato.
- **Cero dependencias.** El smoke es stdlib-only (sin torch). `torch-smoke`
  se auto-registra si hay torch/CUDA. El protocolo `crisol/protocol.py` es la
  única fuente de verdad y no importa nada fuera de la stdlib.

**Roadmap:** más kernels medibles (FP16 matmul, attention, tok/s), transporte
SSH para el laboratorio 2-5, y dashboard web para comparar runs.
